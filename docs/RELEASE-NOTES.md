A running draft of what the first release can honestly say. A line moves up only when its code has merged, and changes its mark only when there is evidence.
`docs/FEATURES.md` (generated) has the item-by-item comparison; `CHANGELOG.md` is the documenter's.

Last brought up to date: 2026-10-14; the head section at the third freeze of that day.

**How sure we are**

| Mark | Means |
|---|---|
| ● | Seen working on a real Mac, on real windows, with real keys or a real pointer where that matters (CI's e2e run or a Mac shell script; the evidence is named) |
| ◐ | Tested against the real controller with simulated windows. The logic is right; nobody has watched it on a Mac |
| ○ | Built, with no test that reaches it. Treat as unproven |

### What is in it

Everything `main` has (dock by drag or key, the Desktop between docked windows, frame, step out and in, walk, back and forward, saved views, gestures, rules, displays that remember), and, new since then:

- **It moves**: every zoom, dock and close is one short motion (F02); during a motion whatever Arbor does not arrange, a pinned call among it, is covered for half a second (`arborctl set animationDuration 0` is the way round). Pictures of the windows themselves ship **off** (`windowPictures`): their only run on a Mac crashed.
- **A face**: buttons in the menu bar, the menu in one decided order, a welcome window that finds what else on the Mac wants the same keys, clicks and drags, three moves to try (F10, F42, F46); `arborctl doctor`. **A line on screen** says what a shortcut did when it failed, when nothing visible changed, and the first few times windows leave the view; ⌃⌥? shows every shortcut in effect (F43).
- **A look**, on by default and **seen by nobody**: the wallpaper is a quarter darker behind docked windows (one rounded surface a display, never over the Desktop), a hairline round the Desktop, redrawn tiles (the app's colour and icon, no caption unless the space has a name; a group as a miniature with a count) that fade in, a white handle in the gap under the pointer (F15, F36).
  The way out, a line each: `arborctl set dimBehindArranged 0` and `arborctl set desktopEdge 0` remove the surface; `arborctl set tileStyle name` brings captions back; `arborctl set gapHandles hidden`. All are in the settings window under Appearance.
- **Ways out**: pause (⌃⌥⎋, F40), Float All Windows on every display, Show Everything on every display (⌃⌥0). **Undo** (⌃⌥Z, ⌃⌥⇧Z): the last change to the arrangement, however it was made, with the view, the history and the saved views it cost; fifty steps a display; the menu names the step (F19). **Arbor notices when its permission is taken away**: within three seconds it stops, says how many windows are out of view and of which apps, and brings everything into view the moment the permission is back (F63).
- **Calls and shared screens**: Hold This View: nothing moves the view, not even your own keys, until ⌃⌥⎋. Hold Still: Arbor moves nothing by itself, your keys, ⌘Tab and Go to… work, and what it turns away it says on screen. Out of the box Arbor holds only when asked; `arborctl set holdStillWhileCameraIsOn true` makes a camera begin it, once that has been seen at work on a Mac (F58).
- **Looking**: peek (hold ⌃⌥Space, F51), a line round the focused window (F37), ⌘Tab from a framed window frames the next one, names for spaces (⌃⌥N, F20), Go to… (⌃⌥G): a few letters of an app, a window or a name (F27), a minimap on ⌃⌥M, which never shows by itself (F26), ⌃⌥-drag frames a rectangle (F05, #207).
- **Arranging**: drags with modifiers (F09), room before tiles (F61), groups that stay groups (F62), a floated window gets its own size and place back (F48), learned sizes expire (F45), a window that floats alone (F18), the layout as a line of text (F54), automatic docking of new windows, which ships **off** (F23).
- **Windows with a will of their own**: keep in view (F49), summon (F53), new windows while framed (F57), dialogs out of view (F47), full screen (F30).
- **New since the first freeze, besides undo and the permission**: the behaviour switches TrellisWM has (F33; their defaults change nothing a person meets); keyboard tiling tools (F22); Go to… keeps itself out of a shared screen; a display's name never reaches a trace.
- **Whose keys**: apps that keep ⌃⌥ (F41), shortcuts that follow the keyboard layout (F44) and the display you type on (F56), zooming with a mouse (F55).
- **Installing**: `make install`, a signing identity of the Mac's own so that the permission survives rebuilds, one version line everywhere (F13). Install, uninstall, `make run` and the identity script decline when nobody is at a terminal. `make uninstall` looks first: if windows are still out of view once Arbor has quit it removes nothing and says what to do; `make install` copies the new app beside the old one before it asks anybody to quit.
- **Settings**: `arborctl set`, `get`, `reset`, `bind`, `rule`; `settings.json` is applied as soon as it is saved, and a mistake in it is named with line and column while the last good settings stay (F12). A settings window (⌃⌥,), seen by nobody yet.
- **For scripts**: `arborctl watch` streams what happens, one line of JSON an event; exit codes that mean something (F24). Gaps and other options per display (F25).
- **Telling us**: traces (F28): `arborctl trace on`, and what was recorded replays on any machine as a test.

Tab groups, the second step of the motion (pictures of the windows while they move), double-click on a title bar, continuous zoom, arrange styles, presets, scripting and carrying windows along are built and are not in this candidate.

### Proven on real windows

All of it on **test windows**, on macOS 26.6, by programs. None of it by a person; none with Safari, Slack, Terminal or Zoom; one display; no lid, no hang, no hold.

- **No Mac has compiled, tested or run this commit.** A Mac built and unit-tested the trunk up to `c0717e6e` (3586 + 14 + 1821 tests); what landed after it has been compiled on Linux and type-checked against stand-ins only. Each of its 61 macOS-only files (what `Package.swift` leaves out elsewhere: `AX`, `App`, `Input` and `UI` in `Sources/ArborKit`, and `Sources/Arbor`, `arbor-e2e` and `ArborTestWindows`) is byte for byte what some build on a Mac compiled, though never all in one build, and nothing that landed after the second freeze touches one. It is the one fault of the day that was proven on a Mac (table below).
- **The last whole real-window runs: 351 checks of 351, twice**: on the first freeze's code and little more, and on a branch that also holds undo, the behaviour switches and the lost permission. Neither holds anything that landed later.
- The first freeze on a Mac: build ✔, 4492 of 4492 unit tests, both smoke runs ✔, 41 scenarios ✔, and `make app` as `make install` runs it (`-c release`, bundle, stamps, ad hoc signature). Nearly every earlier head was built, unit-tested and played in the same way.

Thirty seconds because Arbor hears of the displays a second and a half after the LAST of several notices, and nobody has measured how far apart those come; at two seconds, as first built, the fault came back whole in a play with time in it. ## In one paragraph

Arbor is a free, open-source window manager for macOS in the manner of TrellisWM: dock real windows into nested spaces, keep the Desktop between them, and zoom between spaces. It has no window limit, no trial and no account. It already does the core of what
TrellisWM does, adds a keyboard and a command line for all of it, and is careful about never losing a window. Since this morning it moves: every zoom, dock and close is one short motion. Tab groups have no strip yet.

## What a person still has to try before anyone else is invited

1. A whole working day on real apps: browser, chat, terminal, a call, a shared screen.
2. Pinch, on a real trackpad. Hold ⌃⌥Space and let go.
3. Unplugging and plugging a real display; sleep and wake; a laptop lid.
4. Apps known to be awkward: System Settings, Calculator, Terminal with large text, an Electron app, Finder, a Java or Qt app.
5. The line on screen (F43): legible on your wallpaper, helpful or in the way? Does the panel of shortcuts (⌃⌥⇧/) give the keyboard back?
6. Emacs, an IDE or a remote desktop with Shortcuts Off: do its own ⌃⌥ keys arrive?
7. A keyboard layout that is not US; two layouts switched during the day.
8. With `"guardDesktopClicks": true` and macOS's "Click wallpaper to reveal desktop" at its default: click the wallpaper between docked windows. Then an icon, a widget, a rubber band round icons, a file dragged from the Desktop into a docked window; and a click on the wallpaper to dismiss an open menu, Spotlight, Control Centre, a Dock stack; the items of Arbor's own menu; tap to click.
9. ⌘W on an app's last window: the keyboard goes to the window you used before. Welcome, or did the next ⌘N land in the wrong app?
10. Double-click a word in Safari's address field, a browser tab, a toolbar button in a docked window (once F14 is in): the view must stay.
